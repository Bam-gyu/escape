# 함정 놓기

방을 짜고 함정을 배치하는 사람을 위한 문서다. **고치는 파일은 `src/data/rooms.js`
하나뿐이고, 코드는 안 건드린다.**

---

## 0. 작업 고리

```bash
npm start       # http://localhost:8173
npm test        # 방을 고칠 때마다
```

**두 가지 길이 있다.** 화면에서 놓거나, 파일에 숫자를 적거나.

```
화면에서 놓기 (쉽다)              파일에 적기 (정밀하다)
1. H 를 눌러 편집기를 연다         1. rooms.js 에서 숫자를 고친다
2. 그림을 끌어다 방에 놓는다        2. 브라우저 새로고침
3. 놓인 것을 눌러 숫자를 고친다     3. H 로 판정과 눈금을 본다
4. [저장]                          4. npm test
   ↳ rooms.js 가 다시 써지고
     검사가 그 자리에서 돈다
```

둘 다 같은 파일을 고친다. 섞어 써도 된다 — 편집기로 대충 놓고 파일에서 다듬는 것이
제일 빠르다. **어느 쪽이든 마지막은 직접 해보는 것이다. 재미는 검사가 못 본다.**

| 주소 뒤에 | |
|---|---|
| `?room=4` | 4번 방부터 연다. 앞 방을 매번 다시 깨지 않아도 된다 |
| `?mute=1` | 소리를 끈다 |

| 키 | |
|---|---|
| **H** | **방 편집기를 연다. 방을 짤 때는 이걸 켜고 한다** |
| M | 소리 껐다 켜기 |
| Delete | 고른 것을 지운다 |

### H를 켜면 나오는 것

화면 쪽:

- **빨간 선** — 실제 판정. 그림이 아니라 이게 맞는다
- **눈금** — 120씩. 가로 8칸, 세로 6칸으로 떨어진다
- **노란 숫자** — 커서가 지금 있는 좌표
- **노란 네모**는 출구, **초록 네모**는 소품, **초록 동그라미**는 시작 자리다
- **들키지 않는다.** 함정 위에 커서를 올려야 하니 죽으면 아무것도 못 놓는다

패널 쪽:

- **방 고르기** — 여섯 방 사이를 오간다
- **시간** — `멈춤`으로 세우고, 막대로 아무 순간이나 골라 본다.
  **움직이는 함정은 시간을 세워놓고 놓는 것이 맞다**
- **서랍** — 그림을 끌어다 화면에 놓으면 그 자리에 생긴다
- **[저장]** — `src/data/rooms.js`를 다시 쓰고, 검사를 돌려 결과를 바로 보여준다

## 0.5. 편집기로 놓기

**끌어다 놓으면 그림에 맞는 것이 나온다.** 경비를 놓으면 시야가, 차단바를 놓으면
도는 막대가, 카트를 놓으면 오가는 것이 된다. 놓고 나서 종류를 바꿔도 된다.

| 하는 일 | |
|---|---|
| 놓기 | 서랍의 그림을 캔버스로 끈다 |
| 고르기 | 놓인 것을 누른다. **나중에 놓은 것이 먼저 집힌다** |
| 옮기기 | 집어서 끈다 |
| 지우기 | 고른 뒤 Delete, 또는 패널의 [지우기] |
| 숫자 | 패널의 칸에 적는다. 화면이 즉시 바뀐다 |

**시야와 도는 막대는 발밑·축을 눌러야 집힌다.** 부채꼴 안쪽 아무 데나 눌러서
집히게 하면, 시야가 넓어서 그 아래 있는 것을 영영 못 고르게 된다.

저장을 누르면 검사가 돌고 결과가 패널에 뜬다.

```
저장했다. 검사도 통과했다.        ← 초록
저장은 했는데 검사가 깨졌다.       ← 분홍. 어느 검사가 깨졌는지 같이 나온다
```

**깨져도 파일은 이미 써진 상태다.** 되돌리려면 `git checkout src/data/rooms.js`.

## 1. 좌표계

방은 **960 × 720**. 왼쪽 위가 `0, 0` 이고 **y는 아래로 커진다.**

```
 0,0 ────────────────────────────────── 960,0
  │                                        │
  │        120  240  360  480  600         │
  │                                        │
  │   ← x가 커지는 쪽                       │
  │   ↓ y가 커지는 쪽                       │
  │                                        │
 0,720 ─────────────────────────────── 960,720
```

**사각형 함정(`rect` `blink` `mover`)의 `x, y`는 왼쪽 위 모서리다.**
**`spinner`의 `x, y`만 중심이고, `cone`의 `x, y`는 사람이 서 있는 발밑이다.**
이 셋이 다르다는 것이 제일 자주 걸린다.

## 2. 방 한 덩이

```js
{
    name: '헬스장',              // 화면 왼쪽 위에 뜬다
    background: 'bgGym',         // 배경 그림. src/view/art.js 의 이름
    spawn: { x: 480, y: 650 },   // 시작 자리
    exit: { x: 890, y: 535, w: 60, h: 105, art: 'exitSide' },
    hazards: [ ... ],            // 닿으면 들키는 것
    props: [ ... ],              // 판정 없는 장식
}
```

`background`는 960×720 한 장이다. 없으면 단색 바닥이 깔린다.
`exit`에 `art`를 안 적으면 편의점 유리문(`exit`)이 나온다. 보통 문은 `exitSide`다.

## 3. 함정 다섯 가지

### `rect` — 가만히 있는 것

벽, 난간, 음식 미끼.

```js
{ kind: 'rect', x: 225, y: 470, w: 120, h: 96, art: 'tteokbokki' }
```

`x, y`는 **왼쪽 위 모서리**. `w, h`는 크기.

### `blink` — 깜빡이는 것

센서, 복도등. **`period`초마다 `on`초 동안만 죽인다.**

```js
{ kind: 'blink', x: 470, y: 300, w: 48, h: 60, period: 2.0, on: 1.0, art: 'sensor' }
```

위의 것은 2초 주기로 **1초 켜지고 1초 꺼진다.** `on`을 `period`보다 작게 준다.
`on`이 짧을수록 쉽다 — `period: 3, on: 0.6` 이면 거의 안 걸린다.

**꺼져 있을 때는 그림도 어두워진다.** 플레이어가 지금 켜졌는지 눈으로 알 수 있다.

### `mover` — 왕복하는 것

청소 카트.

```js
{ kind: 'mover', x: 250, y: 560, w: 140, h: 34, dx: 300, period: 4.4, art: 'cart' }
```

`x, y`에서 **`dx`만큼 오른쪽으로 갔다가 돌아온다.** 위의 것은 x 250에서 550까지.

- `dx`를 음수로 주면 왼쪽으로 간다
- `dy`를 주면 위아래로 움직인다. 둘 다 주면 대각선
- `period`는 **한 번 왕복하는 데 걸리는 시간**이다. 작을수록 빠르다

### `spinner` — 도는 막대

주차장 차단바.

```js
{ kind: 'spinner', x: 480, y: 400, length: 300, thickness: 22, period: 5.0, art: 'gate' }
```

**`x, y`가 축(중심)이다.** 막대가 그 자리를 중심으로 돈다.
`length`가 전체 길이라서 **양쪽으로 `length / 2`씩 뻗는다** — 위의 것은 중심에서 150씩.

- `period`는 **한 바퀴 도는 시간**. 음수면 **반대 방향**으로 돈다
- `from`을 주면 시작 각도가 그만큼 돌아간 상태로 시작한다
- 왕복이 아니라 계속 한 방향으로 돈다

막대 둘을 나란히 놓을 때는 한쪽 `period`를 음수로 줘서 서로 반대로 돌게 하면
지나갈 틈이 규칙적으로 열린다.

### `cone` — 시야

매니저와 경비가 보는 범위. **가장 손이 많이 가는 함정이라 따로 아래에 적는다.**

## 4. 시야(`cone`) 자세히

```js
{
    kind: 'cone',
    x: 430, y: 235,      // 사람이 서 있는 자리 (발밑)
    radius: 200,         // 얼마나 멀리 보나
    spread: 46,          // 부채꼴이 몇 도로 벌어지나
    from: 55, to: 125,   // 이 각도 사이를 훑는다
    period: 3.6,         // 한 번 훑고 돌아오는 시간
    art: 'guard',
}
```

### 각도가 헷갈리는 지점

**0도가 오른쪽, 90도가 아래쪽이다.** 화면 좌표라 y가 아래로 커지기 때문에
수학 시간에 배운 것과 위아래가 뒤집혀 있다.

```
            270 (위)
              │
   180 ───────┼─────── 0 (오른쪽)
   (왼쪽)     │
             90 (아래)
```

| 어디를 보게 하려면 | 각도 |
|---|---|
| 아래 (방 안쪽) | **90** |
| 오른쪽 아래 | 45 |
| 왼쪽 아래 | 135 |
| 오른쪽 | 0 |
| 왼쪽 | 180 |
| 위 | 270 |

**위쪽 벽에 선 사람은 거의 항상 90 근처를 본다.** `from: 55, to: 125` 처럼
90을 가운데 두고 양쪽으로 벌리면 자연스럽게 좌우로 훑는다.

### 세 숫자의 뜻

- **`spread`** — 부채꼴이 벌어진 각도. 한 순간에 보이는 넓이.
  40~50이 보통이다. 60을 넘으면 피할 틈이 거의 없다
- **`from` → `to`** — 고개를 돌리는 범위. `to - from`이 클수록 넓게 감시한다
- **`period`** — `from`에서 `to`까지 갔다가 돌아오는 데 걸리는 시간.
  작을수록 빠르게 두리번거린다. 3~4초가 보통이다

**가만히 한 곳만 보게 하려면 `from`과 `to`를 같게 준다.**

### 순찰 — 시야를 든 채 걷는다

`dx` / `dy`를 더하면 사람이 왕복한다.

```js
{
    kind: 'cone', x: 745, y: 300, radius: 165, spread: 48,
    from: 105, to: 165, period: 3.4,
    dx: -470, walkPeriod: 6.4,          // ← 이 둘이 순찰
    art: 'guard',
}
```

- `dx`, `dy` — `mover`와 같다. 그만큼 갔다가 돌아온다
- `walkPeriod` — **걷는 주기.** 안 주면 보는 주기(`period`)와 같아진다
- `walkOffset` — 걷기 시작 박자를 민다

**`walkPeriod`는 `period`와 반드시 다르게 줘라.**
같으면 "오른쪽으로 갈 때는 늘 오른쪽을 본다"가 되어 **안전한 쪽이 한 방향으로
굳는다.** 방을 한 번 보면 끝나는 것이 된다. 위의 예는 보는 주기 3.4초, 걷는 주기
6.4초라서 같은 자리에 와도 매번 다른 곳을 본다.

### 시야를 놓을 때 재는 법

`H`를 켜고 커서를 옮기면 빨간 부채꼴이 지금 어디까지 닿는지 그대로 보인다.
**`radius`를 정할 때는 눈금 한 칸이 120이라는 것을 쓰면 빠르다** — 두 칸이면 240.

## 5. 공통으로 쓸 수 있는 것

### `offset` — 박자 밀기

모든 함정에 줄 수 있다. 단위는 초.

```js
{ kind: 'blink', ..., period: 2.0, on: 1.0, offset: 0.7 }
```

**함정 여럿을 같은 주기로 놓으면 다 같이 움직여서 심심해진다.** `offset`을
조금씩 다르게 주면 어긋나게 움직인다. 카트 셋을 `0`, `0.5`, `1.1`처럼.

### `art` — 그림 고르기

`src/view/art.js`에 있는 이름을 적는다. 안 적으면 색 도형으로 그린다.

```
wall  rail  cart  sensor  lamp  gate  crack       함정
tteokbokki  chicken  ramen                        음식 미끼
guard  manager                                    사람 (cone 전용)
exit  exitSide                                    문
sofa vending plant locker shoes car trash sign    소품
```

**`cone`의 `art`는 `manager`냐 `guard`냐만 본다.** 매니저는 숙소 안, 경비는 바깥.

### `inBackground: true` — 배경이 이미 그린 것

```js
{ kind: 'rect', x: 0, y: 0, w: 960, h: 159, inBackground: true }
```

**판정만 있고 그림은 안 그린다.** 배경 그림에 이미 건물 벽이 그려져 있을 때 쓴다.
안 붙이면 배경 위에 검은 네모가 덧칠돼서 배경이 가려진다.

방마다 **위쪽 건물 띠를 이걸로 막아둔다.** 안 막으면 플레이어가 건물 안으로
걸어 들어간다. 띠의 높이는 배경마다 다르니 `H`로 재서 맞춘다.

출구가 그 띠 안에 있으면 **좌우로 쪼개서** 출구 자리를 비운다.

```js
{ kind: 'rect', x: 0,   y: 0, w: 434, h: 232, inBackground: true },
{ kind: 'rect', x: 526, y: 0, w: 434, h: 232, inBackground: true },
// 434 ~ 526 사이가 비어 있고, 거기에 출구가 있다
```

### `hidden: true` — 안 보이는 함정

**판정은 살아 있고 그림만 안 그린다.** 한 번 당하면 그 방에 있는 동안 드러난다.

**마지막 방에만 둘 수 있다.** 다른 방에 넣으면 검사가 막는다 — 아직 규칙도
모르는 사람이 안 보이는 것에 당하면 농담이 아니라 사고가 되기 때문이다.

**시작 자리에서 90px 안에도 못 둔다.** 들어서자마자 당하면 뭘 잘못했는지 알 수 없다.

## 6. `npm test`가 대신 봐주는 것

숫자를 고쳤으면 이것만 돌리면 된다. 1초 안에 끝난다.

| 검사 | 막아주는 사고 |
|---|---|
| **시작 자리가 15초 내내 안전한가** | 아무것도 안 했는데 죽는 방. 한 점이 아니라 **반경 26 원 전체**를 본다 |
| **출구에 설 수 있는 순간이 있는가** | **못 깨는 방.** 제일 중요하다 |
| 시작하자마자 깨지지 않는가 | 시작 자리가 출구 안에 들어간 방 |
| 숨은 함정이 마지막 방에만 있는가 | 배우기 전에 당하는 것 |
| 숨은 함정이 시작 자리에서 90px 밖인가 | 들어서자마자 당하는 것 |
| 소품이 벽에 묻히지 않았는가 | 영영 안 보이는 장식 |

검사가 깨지면 **어느 방이 몇 초에 문제인지**까지 말해준다.

```
헬스장: 시작 자리가 10.20초에 죽는다
편의점: 출구가 늘 막혀 있다
```

### 검사가 못 보는 것

**재미와 난이도.** 깰 수 있는 방과 재미있는 방은 다르다. 그건 직접 해봐야 안다.

## 7. 난이도를 만드는 법

### 방 하나에 새 장치는 하나만

지금 여섯 방이 그렇게 되어 있다.

| 방 | 새로 나오는 것 |
|---|---|
| 1 헬스장 | 시야 하나 (튜토리얼) |
| 2 헬스장 외부 | 오가는 카트 |
| 3 편의점 | 음식 미끼, 시야 둘 |
| 4 숙소 외부 | 도는 차단바 |
| 5 숙소 거실 | 센서 + 순찰 |
| 6 주인공 방 | 전부 + 안 보이는 함정 |

**한 방에 새 장치를 둘 이상 넣으면 죽었을 때 뭐에 죽었는지 모른다.**

### 어려움을 올리는 손잡이 — 센 것부터

1. **함정 사이의 틈을 좁힌다.** 제일 강하다
2. **주기를 짧게 한다.** `period`를 줄이면 다 빨라진다
3. **`offset`을 어긋나게 한다.** 안전한 박자가 사라진다
4. **`spread`를 넓힌다.** 시야는 45를 넘기면 급격히 어려워진다
5. **함정을 하나 더 놓는다.** 제일 약하고 제일 지저분하다

### 피해야 하는 것

- **시작 자리 근처에 함정을 두는 것.** 반응할 시간이 없다
- **출구 바로 앞의 좁은 틈.** 다 와서 죽는 게 반복되면 그만둔다
- **주기가 다 같은 함정 여럿.** 한 박자만 외우면 끝나는 방이 된다
- **화면 밖에서 갑자기 들어오는 것.** 볼 수 없는 것은 피할 수 없다

## 8. 자주 걸리는 것

| 증상 | 원인 |
|---|---|
| 고쳤는데 화면이 그대로다 | 강제 새로고침(⌘⇧R)을 안 했다 |
| 방이 안 나오고 화면이 멈춘다 | `kind` 오타. 모르는 종류면 일부러 터뜨린다 |
| 배경 위에 검은 네모가 있다 | 벽에 `inBackground: true`를 안 붙였다 |
| 막대가 엉뚱한 데서 돈다 | `spinner`의 `x, y`는 중심이다. 모서리가 아니다 |
| 사람이 엉뚱한 곳을 본다 | 각도는 0이 오른쪽, **90이 아래쪽**이다 |
| 시야가 늘 같은 쪽만 비운다 | `walkPeriod`가 `period`와 같다. 다르게 줘라 |
| 시작하자마자 죽는다 | `npm test`가 몇 초에 죽는지 알려준다 |
| 아무리 해도 못 깬다 | `npm test`의 "출구가 늘 막혀 있다" |

## 9. 새 방을 통째로 만들 때

`ROOMS` 배열에 덩이를 하나 더 넣는다. **코드는 안 건드린다.**

1. 배경을 `art/`에 넣고 `src/view/art.js`에 이름을 등록한다 (960×720)
2. `H`를 켜고 배경을 보며 **건물 띠의 높이**를 잰다 → `inBackground` 벽
3. **출구 자리**를 정한다. 배경에 그려진 문 위가 자연스럽다
4. **시작 자리**를 출구에서 먼 쪽에 둔다. 보통 아래쪽 가운데
5. 함정을 하나씩 놓으면서 매번 `H`로 확인한다
6. `npm test`
7. 직접 끝까지 해본다

**1번 방의 `spawn`을 옮길 때는 주의한다.** 시작 연출의 [문을 연다] 버튼이
1번 방 시작 자리 위에 올라가 있어서, 버튼도 같이 따라 움직인다.
