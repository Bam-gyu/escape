# 숙소탈출 — 이어받는 사람에게

2026-09-17 기준. 이 문서 하나로 시작할 수 있게 적었다. 앞 대화를 안 읽어도 된다.

---

## 1. 무엇을 만들고 있나

**마우스 피하기 게임.** 주인공은 아이돌이고, **숙소에서 몰래 빠져나와 감시망을
피해 편의점에 간식을 사러 간다.**

커서를 따라 아이돌이 움직인다. 함정에 닿으면 **들켜서** 그 구역을 다시 시작한다.
출구에 닿으면 다음 구역으로 간다. 들킨 횟수가 쌓인다.

장르의 뼈대는 YunoGT의 「감옥탈출 리마스터」에서 가져왔다
(https://vidkidz.tistory.com/155). **규칙과 장치는 원작을 따르는 습작이고,
설정·그림·소리·방 배치는 우리 것이다.**

### 원작을 직접 해보고 확인한 것 — 규칙의 근거다

추측이 아니라 플레이해서 본 것만 적는다.

- 주인공이 커서에 **딱 붙는다.** 지연도 관성도 없고, 커서는 발밑에 온다
- 함정에 닿으면 **즉사**한다. 바로 그 방을 다시 시작한다
- 게임 안내문이 스스로 "마우스 피하기 방식입니다"라고 밝힌다
- 사람도 65~290번 죽고 깨는 게임이다. 여러 번 죽는 것이 정상이다
- 그림은 도트가 아니라 **굵은 검은 외곽선 손그림**이다

## 2. 이미 정해진 것 — 다시 논의하지 말 것

사용자와 합의가 끝난 사항이다. 바꾸려면 먼저 사용자에게 물어야 한다.

| 결정 | 내용 |
|---|---|
| 설정 | **아이돌이 숙소에서 몰래 나와 편의점에 간다.** 감옥이 아니다 |
| 위치 | 습작. 규칙은 원작대로, 설정·그림·소리·방 배치는 우리 것 |
| 시작 화면 | **이름·죄목 입력은 없앴다.** 타이틀 → 불 끄는 연출 → 버튼으로 시작 |
| 보스 | **없다.** 원작의 보스 방은 뺐다 |
| 히든 맵 | 없다 |
| 방 수 | **6개.** 순서는 헬스장 → 헬스장 외부 → 편의점 → 숙소 외부 → 숙소 거실 → 주인공 방 |
| 그림 | 손그림. **도트는 안 쓴다** — 32px 격자에 원작의 맛이 안 들어간다 |
| 소리 | Re 프로젝트에서 가져왔다. 설정이 바뀌어도 그대로 쓴다 |
| 주인공 | **아이돌 둘이 붙어 있는 한 덩이.** 혼자가 아니다 |
| 바탕 | 웹. 유니티 안 쓴다 |
| 의존성 | **없다.** npm install도 빌드 도구도 안 쓴다 |

### 규칙을 하나로 합친 것

설계 초안에서는 벽을 "못 지나감", 철창을 "죽음"으로 나눴다. **둘 다 죽음으로 합쳤다.**

막히는 벽을 따로 두면 커서가 벽 안에 있을 때 주인공을 어디에 둘지부터 정해야 한다.
규칙이 하나면 판정 코드가 절반이 되고, 플레이어에게도 설명할 것이 없다.

방 밖으로 나가는 것만 예외다. 가장자리에서 붙잡는다.

### 설계의 핵심 셋

**하나. 그림과 판정을 분리했다.** 게임이 보는 것은 도형뿐이다. 그림은 위에 얹힌
장식이고, 게임은 그림이 있는지도 모른다. **설정을 감옥에서 아이돌로 통째로 바꾸면서
규칙층을 한 줄도 안 고친 것이 이 분리의 값이다.** 안 보이는 함정이 거의 공짜로
들어간 것도 같은 이유다 — 그림을 빼도 게임에게는 아무 일도 안 일어난다.

**둘. 방은 데이터다.** 방 하나 = 데이터 덩이 하나. 방을 늘리는 데 코드도 그림도 안 늘어난다.

**셋. 함정은 상태를 안 든다.** 시간만 넣으면 모양이 정해진다. 안 보이는 함정의
"당했다"는 기억조차 함정이 아니라 `main.js`가 든다.

## 6. 방 추가하기

`src/data/rooms.js`에 덩이를 하나 더 넣는다. **코드는 안 건드린다.**

방은 960×720. 왼쪽 위가 0,0이고 **y는 아래로 커진다.**

| 함정 | 값 | 하는 일 |
|---|---|---|
| `rect` | `x y w h` | 가만히 있는다. 벽, 난간, 잠긴 문 |
| `blink` | 위 + `period on` | `period`초마다 `on`초 동안만 죽인다. 센서, 복도등 |
| `mover` | 위 + `dx dy period` | 제자리에서 그만큼 왕복. 청소 카트 |
| `spinner` | `x y length thickness period` | **x·y를 축으로 도는 막대.** 차단바. `period`가 음수면 반대로 |
| `cone` | `x y radius spread from to period` | 매니저·경비의 시야. **각도는 0이 오른쪽, 90이 아래쪽** |

`travel`은 종류가 아니라 **얹는 것**이다. 어느 함정에든 주면 그만큼 한 방향으로
흘러가 사라졌다가 다시 나온다. `mover`와 달리 왕복하지 않는다.

```js
travel: { dx: 1300, dy: 0, duration: 4.6, gap: 2.4, loop: true }
```

`cone`에 `dx dy walkPeriod`를 주면 **시야를 든 채 순찰한다.** `walkPeriod`를
보는 주기와 다르게 줘야 한다 — 같으면 "오른쪽으로 갈 때는 늘 오른쪽을 본다"가 되어
안전한 쪽이 고정되고 방이 한 번 보면 끝난다.

`offset`(초)을 주면 시작 박자가 밀린다. `art`에 이름을 적으면 그 그림으로 그린다.

`hidden: true`를 주면 **그림을 안 그린다.** 판정은 그대로다. 한 번 당하면
그 방에 있는 동안 드러난다.

**방을 넣었으면 `npm test`를 돌린다.** 검사가 대신 봐주는 것:

- 시작 자리가 15초 내내 안전한가 — 안 그러면 아무것도 안 했는데 죽는 방이 된다
- 출구에 설 수 있는 순간이 있는가 — **못 깨는 방을 막는다.**
  출구 한가운데가 아니라 **출구 전체**를 훑는다
- 숨은 함정이 마지막 방에만 있고, 시작 자리에서 90px 밖인가
- 소품이 벽에 묻혀 영영 안 보이지 않는가

**검사는 "깰 수 없게 된 방"만 막는다. 취향은 안 막는다.** 음식을 헬스장에 놓든
소파를 함정으로 쓰든 아무 말도 안 한다 — 방을 짜는 사람이 정할 일이다.
검사가 멀쩡한 배치를 막기 시작하면 방 짜는 사람이 검사를 안 믿게 된다.

## 8. 소리 바꾸기

`audio/`의 파일을 갈아끼운다. 이름은 `src/view/audio.js`에 있는 것과 맞아야 한다.

```
title-bgm.mp3    타이틀·연출·엔딩 — 게임 밖
stage-bgm.mp3    방에 들어간 뒤 — 게임 안
title-select.mp3 버튼에 커서가 닿을 때
click.mp3        버튼을 누를 때
```

**효과음은 버튼 소리 둘뿐이다.** 들킬 때·구역을 지날 때·도착할 때 소리는
안 쓰기로 했다. 다시 넣으려면 `audio.js`의 `SOUNDS`에 이름을 더하고
`main.js`에서 `audio.play('...')`를 부르면 된다.

**파일 이름은 소문자로 둔다.** macOS는 대소문자를 안 가리지만 올리는 서버는
가린다 — `Click.mp3`로 두면 내 컴퓨터에서만 나고 배포하면 조용해진다. 검사가 본다.

**타이틀곡이 타이틀 화면에서 나게 하려면 "떠나지 않는 첫 클릭"이 필요하다.**

브라우저는 사람이 한 번 건드리기 전까지 소리를 막는다. 그런데 이 게임의 첫 클릭은
`[게임 시작]`이고, **그게 곧 타이틀을 떠나는 클릭이다.** 그래서 첫 방문에서는
타이틀곡이 제 화면에서 날 틈이 없었다 — 한 번 깨고 돌아오면 그때야 들렸다.
이미 건드린 뒤라 바로 나기 때문이다.

그래서 `#gate`("화면을 눌러 시작")를 타이틀 앞에 세운다. **막혀 있을 때만 나온다** —
돌아온 방문에서는 아예 안 뜨므로 클릭이 늘지 않는다. `audio.blocked`가 그 판단이다.

**브라우저는 사람이 한 번 건드리기 전까지 소리를 막는다.** 그래서 처음 열었을 때
타이틀 음악이 조용히 실패한다. `audio.js`가 첫 손길(`pointerdown`·`keydown`)에
한 번 더 걸어본다. 이걸 지우면 타이틀 음악이 안 나오는 채로 남는다.

Re에는 SFX 26개, BGM 12개가 있다. 전부 mp3라 변환 없이 바로 쓴다.

## 9. 걸리기 쉬운 것

**규칙 층에 화면 이야기를 넣지 말 것.** `src/rules/`는 캔버스도 DOM도 `window`도 모른다.
이게 깨지는 순간 검사가 브라우저를 요구하게 되고, 42개가 다 못 돌게 된다.

**함정에 상태를 들리지 말 것.** 지금은 시간만 넣으면 모양이 정해진다. 함정이 스스로
무언가를 기억하기 시작하면, 들키고 다시 시작할 때 함정을 되돌리는 코드가 따로
필요해지고 검사에서 시간을 임의로 넣을 수도 없어진다. **안 보이는 함정의 "당했다"는
기억도 그래서 함정이 아니라 `main.js`가 든다.**

**죽는 것이 도착보다 먼저다.** 순서를 바꾸면 출구 옆에 함정이 있는 방에서
죽으면서 통과하는 일이 생긴다. 검사가 잡는다.

**소품은 판정이 없다.** 게임이 `props` 목록을 아예 안 본다.

**방과 방 사이에는 커서가 시작 자리에 올 때까지 기다린다**(`READY_RADIUS`, main.js).
이게 없으면 앞 방에서 커서가 있던 자리에 주인공이 튀어나와 그대로 죽는다.
자기가 뭘 잘못했는지 알 수 없는 죽음이라 이 장르에서 가장 나쁘다. 지우지 말 것.
첫 진입만 예외인데, **연출 화면의 버튼이 시작 자리 위에 놓여 같은 일을 하기 때문이다.**
버튼 위치를 옮기려면 1번 방의 `spawn`도 같이 옮겨야 한다.

**터치는 짚은 자리로 옮기지 않는다.** 끈 만큼만 간다 — 트랙패드와 같다.
짚은 자리로 옮기면 손가락이 주인공을 가려 아무것도 안 보이고, 손을 뗐다
다시 짚는 것만으로 함정을 뛰어넘는 꼼수가 된다. 반대로 함정 위를 짚었다는
이유로 즉사하기도 한다.

**터치에서는 click이 안 만들어진다.** 캔버스가 `preventDefault`를 부르기 때문이다.
"아무데나 눌러서 다시" 같은 것을 click에만 적어두면 모바일에서 들킨 뒤
영영 못 빠져나온다. `advanceScreen()`을 클릭과 터치가 같이 쓴다.

**각도는 0이 오른쪽, 90이 아래쪽이다.** 화면 좌표라 y가 아래로 커진다.

**`spinner`의 `x`·`y`는 중심이다.** 다른 함정은 왼쪽 위 모서리인데 이것만 다르다.
`cone`도 중심(사람이 선 발밑)이다. **편집기에서 사고가 제일 많이 난 자리가 여기다** —
종류를 바꿀 때 x·y를 그대로 베끼면 함정이 제 크기의 절반만큼 뛴다.
`defaults.js`의 `centerOf`로 견주고 옮긴다.

**편집기는 "지금 이 순간의 모양"으로 집는다.** 함정이 든 x·y로 집으면 오가는 카트를
화면에서 보이는 곳에서 눌러도 안 집히고 허공에서 집힌다. `pick.js`가 `shapeAt`을
쓰는 이유다. 테두리도 같은 것을 쓴다 — 집는 자리와 보이는 자리가 다르면
어디를 눌러야 하는지 알 수가 없다.

## 10. 다음에 할 일 — 순서대로

1. **여섯 방을 끝까지 직접 해보기.** 배경에 맞춰 함정을 새로 놓았고,
   검사는 "못 깨는 방"만 막아줄 뿐 난이도와 손맛은 못 본다.
   **H로 편집기를 열어 그 자리에서 고치면 된다**
2. **들킴 화면의 손그림.** 지금은 글자뿐이다
3. **모바일 터치 확인.** 코드는 있으나 실제 기기 미확인
4. **배포.** 정적 파일이라 그대로 올라간다

### 새 함정을 만들 때

`hazards.js`의 `shapeAt`에 `case`를 하나 더하고, `render.js`가 그릴 줄 알게 하면 된다.
새 판정 도형이 필요하면 `geometry.js`에 함수를 더하고 `shapeHitsCircle`에 갈래를 얹는다.
**하나를 만들면 모든 방이 그걸 쓴다.**

`shapeAt`은 모르는 종류를 만나면 조용히 넘어가지 않고 터진다. 데이터에 오타를 냈을 때
화면에 아무것도 안 나오고 끝나면 방이 왜 쉬운지 알 수가 없기 때문이다.
