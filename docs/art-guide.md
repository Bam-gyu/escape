## 1. 먼저 알아둘 것 — 그림은 판정이 아니다

이 프로젝트에서 가장 중요한 규칙이다. 이걸 모르면 그림을 잘못 그린다.

**게임이 보는 것은 `src/data/rooms.js`에 적힌 도형뿐이다.** 그림은 그 위에 얹는
장식이고, 게임은 그림이 있는지조차 모른다. 그래서:

- 아이돌 그림이 아무리 커도, 실제로 맞는 판정은 **발밑의 반지름 7짜리 원** 하나다
- 그림을 크게 그려도 게임이 어려워지지 않는다
- 그림을 안 그려도 게임은 똑같이 돌아간다

### 이게 실제로 뜻하는 것

| | |
|---|---|
| **사람은 크게 그려도 된다** | 판정이 발밑 점 하나라서, 몸이 커도 안 걸린다. 오히려 커야 보인다 |
| **함정은 판정 상자를 크게 벗어나면 안 된다** | 벗어난 만큼 "저건 안 맞았는데?"가 된다. 상자 안에 딱 맞게 |
| **소품은 아무렇게나 그려도 된다** | 판정이 아예 없다. 다만 **함정처럼 생기면 안 된다**(아래 참고) |

### 판정과 그림이 얼마나 어긋나는지 보는 법

게임 중에 **`H`** 를 누르면 판정이 빨간 선으로 보인다. 그림과 겹쳐 보면
어긋난 정도가 바로 보인다. **그림을 넣을 때마다 한 번씩 눌러보는 것을 권한다.**

## 2. 화풍

| | |
|---|---|
| 선 | **굵은 검은 외곽선.** 원작의 인상이 여기서 나온다 |
| 채색 | 면을 단색으로 채운다. 그라디언트·에어브러시는 안 쓴다 |
| 질감 | 손그림. 선이 조금 떨려도 된다. 오히려 그게 맛이다 |
| **도트는 안 쓴다** | 32px 격자에 이 맛이 안 들어간다. **이미 정해진 것이라 다시 논의하지 않는다** |

선 굵기는 **표시 크기 기준 2~3px**(내보낼 때는 2배니까 4~6px)이 적당하다.
작은 그림(`sensor` 26×32)과 큰 그림(`sofa` 230×260)의 선 굵기가 같아야
한 화면에 놓였을 때 같은 손이 그린 것으로 보인다. **그림마다 선 굵기를 다르게
하지 마라.** 이게 화풍을 가장 크게 망친다.

### 색조 — 새벽 두 시

전체를 **푸른 밤** 쪽으로 눌러 둔다. 밝은 것은 셋뿐이다: 아이돌, 편의점, 그리고
켜진 불빛.

지금 도형으로 쓰고 있는 색이 기준이다(`src/view/palette.js`). 그림도 이 근처로
맞추면 도형과 그림이 섞여 있어도 안 튄다.

## 3. 기술 규격

| | |
|---|---|
| 형식 | **PNG, 투명 배경** (알파 채널) |
| 크기 | 아래 표의 **"내보낼 크기"** — 표시 크기의 2배다 |
| 색 공간 | sRGB |
| 여백 | **두지 마라.** 그림이 캔버스 가장자리에 닿게 |

### 왜 2배인가

화면에서는 표시 크기로 줄여 그린다. 2배로 그려두면 큰 화면이나 고해상도
디스플레이에서 선명하다. 예를 들어 `idol`은 표에 44×62로 적혀 있으니
**88×124로 그려서 저장**한다.

### 여백을 두면 안 되는 이유

코드는 png를 판정 상자에 **딱 맞춰 늘여 붙인다.** 그림 주위에 빈 공간이 있으면
그만큼 실제 그림이 작아지고, 판정보다 작게 보여서 "안 닿았는데 죽었다"가 된다.

**사람(`idol`·`manager`·`guard`)만 예외다.** 이들은 판정 상자가 아니라
`art.js`에 적힌 고정 크기로 그려지고, 발밑이 기준점이다.

## 4. 그림 목록

이름은 `src/view/art.js`에 있는 것과 **정확히 같아야 한다.**
파일은 `art/<이름>.png` 로 저장한다.

### 4-1. 사람 (3장)

| 이름 | 표시 크기 | **내보낼 크기** | 무엇 |
|---|---|---|---|
| `idol` | 44×62 | **88×124** | 주인공 |
| `manager` | 48×68 | **96×136** | 매니저. 숙소 안(1·3·6번 방) |
| `guard` | 48×68 | **96×136** | 경비. 바깥(5·6번 방) |

**발밑이 기준점이다.** 그림 아래쪽 가운데가 서 있는 자리에 온다.
발이 캔버스 맨 아래 선에 닿게, 좌우로는 가운데에 오게 그린다.

```
 ┌────────────┐  ← 캔버스 위
 │    (머리)   │
 │    (몸통)   │
 │    (다리)   │
 └──[발]──────┘  ← 발이 여기 닿아야 한다. 아래 여백 금지
      ↑
   가로 한가운데
```

**정면 한 장씩만 그리면 된다.** 걷는 동작도, 방향별 그림도 필요 없다.
코드가 그림을 뒤집거나 돌리지 않는다.

`manager`와 `guard`는 **한눈에 구별돼야 한다.** 둘 다 시야 부채꼴을 달고 있어서
헷갈리면 "누가 어느 쪽을 보는지"를 못 읽는다. 매니저는 사복에 후드, 경비는
제복에 모자 — 실루엣부터 다르게.

아이돌은 **변장한 차림**이다. 모자·마스크·후드. 새벽에 몰래 나가는 사람이다.

### 4-2. 함정 — 닿으면 들킨다 (8장)

| 이름 | 쓰이는 크기 | **내보낼 크기** | 무엇 |
|---|---|---|---|
| `wall` | 타일 120×120 | **240×240** | 벽. **가로세로로 반복** |
| `rail` | 두께 36~50 | **200×100** | 난간, 잠긴 문. **가로로 반복** |
| `cart` | 120×30, 130×28 | **260×60** | 청소 카트. 한 장으로 늘여 붙임 |
| `sensor` | 26×32, 48×60 | **96×120** | 동작 감지 센서. **켜진 모습만** |
| `lamp` | 150×26 | **300×52** | 깜빡이는 복도등. **가로로 반복, 켜진 모습만** |
| `gate` | 300~360 × 22 | **720×44** | 주차장 차단바. **가로로 누운 모습** |

#### 반복되는 그림 — `wall`, `rail`, `lamp`

**이게 제일 까다롭다.** 같은 조각을 이어 붙여 긴 면을 만들기 때문에,
**조각의 끝과 끝이 맞물려야 한다.** 안 맞물리면 이음매가 줄줄이 보인다.

**`wall`은 가로세로 둘 다 반복한다.** 벽은 30×720짜리 기둥부터 960×44짜리 띠까지
있어서 한 장을 늘여 쓸 수가 없다(비율이 21배까지 벌어진다).

- **120×120 타일**로 쓰인다. 그러니 **240×240으로 그린다**
- **왼쪽 끝과 오른쪽 끝, 위쪽 끝과 아래쪽 끝이 각각 이어져야 한다**
- 확인법: 그린 뒤 사방에 복사해 3×3으로 붙여놓고 이음매가 보이는지 본다
- 무늬가 클수록 반복이 티 난다. **잔잔한 결**이 안전하다

**`rail`과 `lamp`는 가로로만 반복한다.** 조각의 **높이가 상자 높이에 맞춰 늘어나고**
가로로 이어 붙는다.

- `rail`은 두께 36·40·50으로 쓰인다. **세 두께에서 다 괜찮아 보여야 한다**
- 세로 창살이 일정 간격으로 있는 무늬가 잘 맞는다. 왼쪽 끝과 오른쪽 끝의
  창살 간격이 이어지게
- `lamp`는 형광등 관 같은 것. 150×26에만 쓰이니 이음매 걱정이 덜하다

#### `gate` — 차단바

**반드시 가로로 누운 모습으로 그린다.** 코드가 돌린다.

```
 ┌──────────────[ ● ]──────────────┐   ← 이 가운데 점이 회전축
 │███░░░███░░░███ │ ███░░░███░░░███│
 └────────────────┴────────────────┘
        ↑ 그림의 정가운데가 축이 된다
```

- **그림의 정가운데가 회전축**이다. 축이 될 자리를 한가운데에 둬야 한다
- 300·330·360 길이로 쓰인다. 두께는 전부 22로 같다
- 빨강·흰색 사선 줄무늬가 차단바의 기호다. 축 쪽에 기계 상자를 그려도 좋다
- 축 자리에는 **코드가 검은 원을 따로 그린다.** 안 그려도 된다

#### `sensor`와 `lamp` — 켜진 모습 한 장만

**꺼진 모습은 그리지 마라.** 코드가 알아서 어둡게 칠한다.

`sensor`는 세로로 긴 비율(0.80)로 쓰인다. 벽에 붙은 작은 감지기 느낌으로.
빨간 렌즈가 하나 있으면 한눈에 읽힌다.

#### `crack` — 안 보이던 함정

당하기 전에는 **안 보인다.** 당하고 나서야 드러난다.
삐걱대는 마룻장, 깨진 보도블록, 벗겨진 타일 같은 것.

드러날 때 코드가 **붉은 점선 테두리를 덧그린다.** 그러니 그림 자체는
"아, 이게 있었구나" 싶은 물건이면 된다. 위험해 보일 필요 없다.

#### `exit`와 `exitSide`

`exit`은 **가로로 넓은 문**(비율 1.45~2.45), `exitSide`는 **세로로 긴 옆문**(0.65)이다.
골목 방만 옆문을 쓴다.

마지막 6번 방의 `exit`은 **편의점 문**이 된다. 152×62로 다른 방보다 넓다.
같은 그림을 쓰지만 여기서 제일 크게 나오니, 밝고 반가워 보이게.

### 4-3. 소품 — 판정이 없다 (8장)

닿아도 아무 일도 안 일어난다. 분위기만 만든다.

| 이름 | 크기 | **내보낼 크기** | 어디 |
|---|---|---|---|
| `sofa` | 230×260 | **460×520** | 숙소 라운지 |
| `vending` | 110×70 | **220×140** | 라운지, 로비 |
| `plant` | 90×90, 80×80 | **180×180** | 라운지, 로비, 주차장 |
| `locker` | 120×86 | **240×172** | 기숙사 복도 |
| `shoes` | 120×86 | **240×172** | 기숙사 복도 |
| `car` | 150×100 | **300×200** | 지하 주차장 |

**소품은 함정처럼 생기면 안 된다.** 이게 소품의 유일한 규칙이다.
플레이어가 피하려다 오히려 진짜 함정에 걸린다.

- 함정보다 **흐리고 어둡게**. 바닥에 깔린 느낌으로
- 외곽선을 함정보다 **얇게**
- 날카롭거나 번쩍이는 것은 피한다

지금 도형으로 그릴 때도 `rgba(210, 220, 240, 0.14)` 로 아주 흐리게 깔고 있다.
그 정도 존재감이 맞다.

## 5. 안 그려도 되는 것

**코드가 그린다. 시간 쓰지 마라.**

- 매니저·경비의 **빨간 시야 부채꼴**
- `sensor`와 `lamp`가 **꺼진** 모습
- 차단바가 **돌아가는** 중간 각도들 (누운 그림 한 장이면 된다)
- 차단바의 **회전축 검은 원**
- 안 보이는 함정이 **드러났을 때의 붉은 점선**
- 타이틀 화면, 연출 화면, 들킴 화면, 도착 화면
- 시작 자리의 **점선 원**
- 바닥

## 8. 넣고 확인하기

```bash
npm start
```

http://localhost:8173 을 연다.

| 어디를 볼까 | 주소 |
|---|---|
| 숙소 라운지 (`idol` `manager` `wall` `rail` `sensor` `sofa` `vending` `plant`) | `?room=1` |
| 기숙사 복도 (`cart` `locker` `shoes`) | `?room=2` |
| 로비 (`manager` 둘, `sensor`) | `?room=3` |
| 지하 주차장 (`gate` `car`) | `?room=4` |
| 밤거리 골목 (`guard` `lamp` `exitSide` `trash` `sign`) | `?room=5` |
| 편의점 앞 (전부 + `crack`) | `?room=6` |

`?mute=1`을 같이 주면 소리가 꺼진다. 그림 보는 동안 조용하다.

**`H`를 누르면 판정이 빨간 선으로 보인다.** 그림이 판정보다 튀어나왔는지
한눈에 확인할 수 있다. 숨은 함정(`crack`)도 여기서는 다 보인다.

파일을 바꾼 뒤에는 **강제 새로고침**(⌘⇧R)을 해야 한다. 그냥 새로고침하면
브라우저가 옛 그림을 계속 쓴다.

### 404는 고장이 아니다

콘솔에 **없는 png 수만큼 404가 뜬다.** 정상이다. 그림을 다 넣으면 사라진다.
이건 "파일이 없으면 도형으로 대신 그린다"는 설계의 부작용이고,
덕분에 한 장씩 넣어가며 작업할 수 있다.

## 9. 흔한 실수

| 증상 | 원인 |
|---|---|
| 그림이 안 나온다 | 파일 이름이 다르다. `art.js`의 이름과 **정확히** 같아야 한다 |
| 그림 둘레에 빈 테두리가 있다 | 캔버스에 여백을 뒀다. 그림이 가장자리에 닿게 다시 |
| 벽에 이음매 줄이 보인다 | `wall` 타일의 끝과 끝이 안 맞물린다. 3×3으로 붙여서 확인 |
| 사람이 공중에 떠 있다 | 발이 캔버스 맨 아래에 안 닿아 있다 |
| 차단바가 엉뚱한 데를 축으로 돈다 | 축이 그림 정가운데가 아니다 |
| 뿌옇게 뭉개진다 | 표시 크기로 그렸다. **2배**로 다시 |
| 흰 배경이 딸려 나온다 | 배경 레이어를 끄지 않고 내보냈다 |
| 안 닿았는데 죽는다 | 함정 그림이 판정 상자보다 작다. `H`로 확인 |
| 닿았는데 안 죽는다 | 함정 그림이 판정 상자보다 크다. `H`로 확인 |
| 소품을 피하다 함정에 걸린다 | 소품이 너무 함정처럼 생겼다. 흐리게 |

## 10. 체크리스트

한 장 끝낼 때마다:

- [ ] 파일 이름이 `art.js`의 이름과 정확히 같은가
- [ ] 투명 배경인가 (흰 배경이 아니라)
- [ ] "내보낼 크기"(표시 크기의 2배)로 저장했는가
- [ ] 그림 둘레에 여백이 없는가
- [ ] 선 굵기가 다른 그림들과 같은가
- [ ] 색이 새벽 두 시 색조 안에 있는가
- [ ] (사람) 발이 캔버스 맨 아래, 좌우 한가운데인가
- [ ] (반복 그림) 끝과 끝이 맞물리는가
- [ ] (`gate`) 가로로 누워 있고 축이 정가운데인가
- [ ] (`sensor`·`lamp`) 켜진 모습인가
- [ ] 브라우저에서 `H`를 눌러 판정과 비교해봤는가
