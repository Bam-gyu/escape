# 감옥탈출 팬 게임 설계

2026-09-16

## 무엇을 만드는가

감옥탈출류(마우스 피하기) 팬 게임. 원작은 YunoGT의 「감옥탈출 리마스터」다.
**규칙과 장치는 원작을 따라 만드는 습작이고, 그림·효과음·음악과 방 배치는 우리 것이다.**

원작을 직접 해보고 확인한 것:

- 죄수가 커서에 **딱 붙는다.** 지연도 관성도 없고 커서는 발밑에 온다
- 함정에 닿으면 **즉사**한다. 손그림 해골이 뜨고 "다시"로 바로 재시작
- 시작할 때 **이름과 죄목**을 적는 수감 카드가 있다
- 죽은 횟수가 쌓인다 (댓글에 "65번 죽고 깼다", "0데스" 같은 말이 오간다)
- 방마다 함정 배치가 다르고, 출구에 닿으면 다음 방

원작에 있으나 **안 만드는 것**: 보스 방, 히든 맵, 이스터에그 이름.

## 큰 결정 두 가지

### 하나. 그림과 판정을 분리한다

게임이 보는 것은 도형뿐이다. 그림은 그 위에 얹힌 장식이고, 게임은 그림이 있는지도 모른다.

이렇게 한 이유는 그림이 아직 없기 때문이다. 그림을 기다리며 멈추는 대신 색 도형으로
먼저 굴리고, 그림이 나오는 대로 파일만 갈아끼운다. **그림이 바뀌어도 게임 코드는 안 바뀐다.**

덤으로 판정이 또렷해진다. 근육 죄수가 화면의 4분의 1을 차지해도 판정 목록에 없으면
게임은 그를 모른다. 판정이 그림 크기에 딸려가지 않는다.

### 둘. 방은 데이터다

방 하나 = 데이터 덩이 하나. 방을 늘리는 데 코드도 그림도 안 늘어난다.

방 수를 미리 정하지 않았기 때문이다. "5방보다는 많이, 몇 방일지는 나중에"가
실제로 가능하려면 방을 늘리는 값이 싸야 한다.

함정 종류를 하나 만들면 모든 방이 그걸 쓴다. 뒤로 갈수록 종류를 하나씩 얹어
어렵게 만드는 것이 이 장르가 하는 일이다.

## 구조

| 층 | 파일 | 하는 일 |
|---|---|---|
| 규칙 | `rules/geometry.js` | 원과 사각형, 원과 부채꼴이 겹치는가 |
| | `rules/hazards.js` | 시간을 넣으면 함정이 지금 어떤 도형인가 |
| | `rules/room.js` | 죄수 자리, 죽었는가, 도착했는가 |
| 데이터 | `data/rooms.js` | 방 목록 |
| 화면 | `view/render.js` | 그림이 있으면 그림, 없으면 도형 |
| | `view/art.js` | 그림 목록. 갈아끼우는 자리 |
| | `view/audio.js` | 소리. 없으면 조용할 뿐 안 멈춘다 |
| 진행 | `main.js` | 화면 넘김, 죽음 세기, 입력 |

규칙 층은 **Unity도 캔버스도 DOM도 모른다.** 순수 함수라 화면 없이 전부 검사된다.

### 함정 네 가지

| 종류 | 모양 | 원작의 무엇 |
|---|---|---|
| `rect` | 고정 사각형 | 벽, 철창 |
| `blink` | 켜졌다 꺼지는 사각형 | 전기 |
| `mover` | 왕복하는 사각형 | 오가는 장애물 |
| `cone` | 좌우로 훑는 부채꼴 | 간수의 시야 |

함정은 **자기 상태를 안 들고 있다.** 시간만 넣으면 모양이 정해진다. 그래서 죽고 다시
시작할 때 함정을 되돌리는 코드가 필요 없고, 되감아도 건너뛰어도 같은 답이 나온다.

### 한 프레임에 하는 일

1. 커서를 읽어 죄수를 거기 놓는다 (방 밖으로는 안 나간다)
2. 시간을 넣어 모든 함정의 지금 모양을 받는다
3. 죄수의 원이 죽는 도형과 겹치는지 본다 — 겹치면 죽음
4. 출구에 닿았으면 다음 방

**죽는 것이 도착보다 먼저다.** 순서가 반대면 출구 옆에 함정이 있는 방에서
죽으면서 통과하는 일이 생긴다.

## 규칙을 하나로 합친 곳

설계 초안에서는 벽을 "못 지나감", 철창을 "죽음"으로 나눴다. **둘 다 죽음으로 합쳤다.**

원작에서 철창에 닿자 즉사했고, 막히는 벽을 따로 두면 커서가 벽 안에 있을 때 죄수를
어디에 둘지부터 정해야 한다. 규칙이 하나면 판정 코드가 절반이 되고,
"닿으면 죽는다"는 플레이어에게도 설명할 것이 없다.

방 밖으로 나가는 것만 예외로 두고 가장자리에서 붙잡는다.

## 방에 들어설 때

방에 들어서면 **커서가 시작 자리에 올 때까지 기다린다.** 그 전에는 시간이 안 흐른다.

없으면 앞 방에서 커서가 있던 자리에 죄수가 튀어나와 그대로 죽는다. 자기가 뭘
잘못했는지 알 수 없는 죽음이라 이 장르에서 가장 나쁜 종류다.

## 검사

27개. `npm test`, 1초 안에 끝난다.

- 도형 겹침 — 모서리, 대각선 꼭짓점, 부채꼴 경계, 간수 등 뒤
- 각도가 0도를 넘어갈 때 짧은 쪽으로 재는가
- 함정이 시간에 따라 제 모양을 찍는가, 모르는 종류에 조용히 넘어가지 않는가
- **시작 자리는 언제나 안전한가** (15초를 1/60씩 훑는다)
- **출구에 설 수 있는 순간이 있는가** — 깰 수 없는 방을 막는다
- 죽는 것이 도착보다 먼저인가
- 소품이 벽에 묻혀 영영 안 보이지 않는가

뒤의 넷은 방 데이터를 검사한다. 방을 새로 넣고 `npm test`만 돌리면
못 깨는 방을 만들어두고 모르는 일이 안 생긴다.

재미와 손맛은 검사가 못 본다. 그건 브라우저에서 직접 한다.

## 남은 것

- 그림 15장 안팎 (죄수, 간수, 벽, 철창, 문, 전기, 장애물, 소품 몇)
- 방을 5개 위로 늘리기
- 죽음 화면의 손그림 해골
- 모바일 터치 확인 — 코드는 넣었으나 실제 기기에서 안 봤다
