# 숙소탈출

마우스 피하기 게임. **아이돌이 숙소에서 몰래 빠져나와 감시망을 피해 편의점에 간다.**

주인공이 커서를 따라다니고, 함정에 닿으면 들키고, 출구에 닿으면 다음 구역으로 간다.
장르의 뼈대는 YunoGT의 「감옥탈출 리마스터」에서 가져온 습작이다.

만드는 도구가 없다. `npm install`도 빌드도 안 한다 — 브라우저와 node만 있으면 된다.

## 돌리기

```
npm start
```

그리고 http://localhost:8173 을 연다. ES 모듈이라 파일을 그냥 두 번 눌러 여는 건 안 된다.

| 주소 뒤에 | 하는 일 |
|---|---|
| `?room=4` | 4번 방부터 시작한다. 방을 짜는 동안 쓴다 |
| `?mute=1` | 소리를 끄고 시작한다 |

| 키 | 하는 일 |
|---|---|
| H | **방 편집기**를 연다. 판정·눈금·좌표가 보이고, 오른쪽 서랍에서 그림을 끌어다 놓는다 |
| M | 소리를 껐다 켠다 |

### 방 편집기

H를 누르면 오른쪽에 서랍이 열린다. 그림을 끌어다 놓으면 그 자리에 함정이 생기고,
놓인 것을 눌러 종류와 숫자를 고친다. **[저장]을 누르면 `src/data/rooms.js`가 다시
써지고 검사가 그 자리에서 돈다.**

방을 짜는 동안만 쓰는 것이라 **localhost에서만 열린다.** 빌드가 없어 파일은 올린 곳에
따라가지만, 올려둔 게임에서는 H를 눌러도 아무 일도 안 일어난다. 불러오는 것도
H를 누른 그 순간이다.

저장은 `npm start`로 띄운 서버에서만 된다. 그 서버는 127.0.0.1에만 열고,
Host·Origin·Content-Type을 봐서 **자기가 연 화면에서 온 요청만** 받는다 —
안 그러면 서버를 켜둔 채 아무 웹페이지나 열었을 때 그 페이지가 방을 덮어쓸 수 있다.

## 검사

```
npm test
```

규칙이 화면을 모르는 순수 함수라 브라우저 없이 다 검사된다. 125개, 1초 안에 끝난다.

## 방 추가하기

**자세한 것은 `docs/hazard-guide.md` 에 있다.** 좌표계, 함정 다섯 가지,
시야 각도, 난이도 만드는 법, 자주 걸리는 것까지 거기 적어뒀다.

줄이면: `src/data/rooms.js`에 덩이를 하나 더 넣는다. **코드는 안 건드린다.**

방 하나는 960×720이다. 왼쪽 위가 0,0이고 y는 아래로 커진다.

```js
{
    name: '편의점 앞',
    spawn: { x: 480, y: 688 },              // 시작 자리
    exit: { x: 404, y: 10, w: 152, h: 62 }, // 여기 닿으면 다음 구역
    hazards: [ ... ],                        // 닿으면 들키는 것
    props: [ ... ],                          // 판정 없는 장식
}
```

함정은 다섯 가지다.

| 종류 | 쓰는 값 | 하는 일 |
|---|---|---|
| `rect` | `x y w h` | 가만히 있는다. 벽, 난간, 잠긴 문 |
| `blink` | 위 + `period on` | `period`초마다 `on`초 동안만 죽인다. 센서, 복도등 |
| `mover` | 위 + `dx dy period` | 제자리에서 그만큼 왕복한다. 청소 카트 |
| `spinner` | `x y length thickness period` | **x·y를 축으로 도는 막대.** 주차장 차단바 |
| `cone` | `x y radius spread from to period` | 매니저·경비의 시야. 각도는 0이 오른쪽, 90이 아래쪽 |

`spinner`의 `x`·`y`는 **중심**이다. 다른 함정은 왼쪽 위 모서리인데 이것만 다르다.
`period`가 음수면 반대로 돈다.

`cone`에 `dx dy walkPeriod`를 주면 **시야를 든 채 순찰한다.** `walkPeriod`는
보는 주기와 다르게 주는 편이 낫다 — 같으면 안전한 쪽이 한 방향으로 고정된다.

`offset`을 주면 시작 박자가 그만큼 밀린다. 함정 여럿을 어긋나게 할 때 쓴다.

`art`에 이름을 적으면 그 그림으로, 안 적으면 색 도형으로 그린다.

`hidden: true`를 주면 **그림을 안 그린다. 판정은 그대로 살아 있다.**
한 번 당하면 그 방에 있는 동안 드러난다. 마지막 방에만 둔다 — 검사가 본다.

방을 넣고 `npm test`를 돌린다. **시작 자리가 안전한지, 출구에 설 수 있는 순간이 있는지**를
검사가 대신 봐준다 — 깰 수 없는 방을 만들어두고 모르는 일이 안 생긴다.

## 그림 넣기

**`docs/art-guide.md`에 규격과 목록이 다 있다.**

줄이면: `art/` 폴더에 투명 배경 png를 표시 크기의 2배로 넣으면 끝이다.
이름은 `src/view/art.js`에 적혀 있다. `idol`과 `manager` 둘만 넣어도
화면이 단번에 달라진다.

**파일이 없으면 색 도형으로 대신 그린다.** 한 장씩 넣어도 되고, 안 넣어도 게임은 돈다.
그림을 넣어도 게임 코드는 안 바뀐다 — 판정은 도형이 따로 갖고 있다.

그래서 **브라우저 콘솔에 없는 png만큼 404가 뜬다. 고장이 아니다.** 다 넣으면 사라진다.

시야 부채꼴, 센서가 꺼진 모습, 차단바가 돌아가는 것, 들킴 화면은 코드가 그린다.
안 그려도 된다.

## 소리 바꾸기

`audio/` 폴더의 파일을 갈아끼운다. 이름은 `src/view/audio.js`에 있는 것과 맞아야 한다.

```
title-bgm.mp3    타이틀·연출·엔딩 — 게임 밖
stage-bgm.mp3    방에 들어간 뒤 — 게임 안
title-select.mp3 버튼에 커서가 닿을 때
click.mp3        버튼을 누를 때
death.mp3        들킬 때
clear.mp3        구역을 지났을 때
win.mp3          편의점 도착
```

**이름은 소문자로 둔다.** macOS는 대소문자를 안 가리지만 올리는 서버는 가린다 —
`Click.mp3`로 두면 내 컴퓨터에서만 나고 배포하면 조용해진다. 검사가 본다.

어느 화면에서 어느 곡이 도는지는 `audio.js`의 `musicFor` 한 곳에서 정한다.
